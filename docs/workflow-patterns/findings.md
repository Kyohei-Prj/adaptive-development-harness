# Findings — workflow-patterns

## 2026-10-20 — Task 1.6
**Question:** Can a throwaway nested git repo under `.scratch/` be driven as an independent repo by our agents — (a) does the outer repo's `git status`/`git add` stay unaffected by it and by commits made inside it, or can it surface as an accidentally-staged gitlink — and (b) do its git operations (`init`, `worktree add`, `-C … commit`) behave independently of the outer repo's hooks/config/branch — making it a safe fixture for the Phase 4.5 `/interactive` and 5.4 `/characterize` dogfoods?

**Approach:** Ran a reproducible experiment in `.scratch/` using only explicit `git -C <path> …` commands: created `.scratch/spike-nested-repo` (`git init -b main`, two commits), checked outer `git status --porcelain` / `git add` / staged index / HEAD+branch around it; probed the embedded-repo mechanism with a second pair `.scratch/spike-outer-fake/fixture` *without* a gitignore to see what a non-ignored nested repo would do; exercised nested-local hooks (`pre-commit` marker file), nested-local config, and `git worktree add` from the nested repo, comparing both repos' worktree lists and HEADs. Fixtures left in place under `.scratch/` (gitignored) for inspection.

**Answer:** (a) Yes, unaffected: with the nested repo existing and holding two commits, outer `git status --porcelain` printed only the pre-existing `?? docs/workflow-patterns/` (nested entirely invisible — `.gitignore:3:.scratch/`), `git add .scratch/spike-nested-repo` was refused (`ignored by one of your .gitignore files`, exit 1) and staged nothing (`git ls-files --stage .scratch` and `git diff --cached` empty), outer HEAD/branch stayed `8b1f53a`/`feature/workflow-patterns-phase-1` throughout. Gitlink risk is real only for *non-ignored* paths: in the no-gitignore fake pair, `git status` showed `?? fixture/` and `git add fixture` staged mode `160000` (`160000 74130e8… 0 fixture`, `A fixture`) — so a real micro-change fixture *in-tree* could be committed as a stray gitlink, while `.scratch/` cannot. (b) Yes, independent: nested commits (848cc25, 81bf578) advanced only nested `main`, never outer HEAD; a nested `pre-commit` hook ran on nested commits while the outer repo (only sample hooks) was never consulted — hook resolution is per-repo `.git/hooks`; `user.name` resolved to "Spike Fixture" from the nested repo's own `.git/config` vs `Kyohei-Prj` (global) in the outer — no config bleed; `git worktree add ../spike-nested-wt -b spike-wt` registered only in the nested repo's `git worktree list`, outer listed solely its own worktree. Both experiment fixtures left in place: `.scratch/spike-nested-repo/` (+ `spike-nested-wt/`, `NESTED_HOOK_RAN`) and `.scratch/spike-outer-fake/`.

**Decision:** Use the nested throwaway repo under `.scratch/` as the fixture for the Phase 4.5 `/interactive` and 5.4 `/characterize` dogfoods — it is provably invisible to the outer repo's status/add (gitignored) and fully independent in hooks/config/branch/worktrees — over a real micro-change in-tree, which the fake-pair experiment shows can be accidentally staged as a mode-160000 gitlink.
